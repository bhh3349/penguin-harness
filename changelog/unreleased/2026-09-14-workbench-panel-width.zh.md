# 工作台那一栏按半栏宽打开，面板里的按钮降了一档

- **Date:** 2026-09-14
- **Type:** change
- **Scope:** `web`

[English](2026-09-14-workbench-panel-width.zh.md)

右侧那一栏**在显示工作台时按窗口的 20% 打开**——1920 宽的窗口上是 384px（原来是 768px）；工作台面板自己那套 chrome（载入、刷新、选择元素、多选、清除、加入对话）画在 **22px 的盒子里、图标 12px**，比应用里其他图标按钮低一档，那些一个没动。这一栏的其他工作面——子代理转录、文件树、终端——**仍然是它们当初被挑中的 40%**。

## 细节

- **默认宽度改成按面板区分**（`features/chat/use-panel-width.ts` 的 `defaultWidthFor(windowWidth, kind)`；唯一自带比例的是 `workbench: 0.2`）。40% 是给"阅读型"工作面挑的：子代理转录（"三分之一窗口会把 tool 输出折成一条窄柱"）与文件树（它在 480px 以下会退化成单栏钻取）——把这两类一起减半，是没人要求的布局变化。
- **只有"默认值"按面板区分，"偏好"仍然只有一个值。** 这一栏的宽度被 dock 里所有面板共用一个值（这样换 tab 不会让整栏跳一下）这条**原封不动**：用户一拖分隔线，`penguin.panelWidth` 里就是那一个宽度，之后每个面板都按它打开（只要存着宽度，`seedPanelWidth` 什么都不做）。没拖过的时候，换个 tab 就按那个面板自己的默认给这一栏定宽；拖过之后，标签条就还是"一栏"。
- **设计系统里新增两档，只被这一块面板用**：`Button size="iconSm"`（`p-1`，连边框 22px 的盒子，`icon` 是 29px）和 `ICON_SIZE.compactButton`（12，`iconButton` 是 15）。`workbench-panel.tsx` 里那六个调用点搬到新档上，应用别处一个没动。
- **按钮为什么跟着宽度一起改**：这一栏的地板是 320px，而它的 chrome 要在那个宽度下把地址、四个控件、一行 chip 都留在一行里。29px 的盒子让地址框挤得太狠，22px 不会。

## 实测

- 新真机脚本 `实测脚本/m61-面板宽度与按钮/`（端口 5195，真桌面壳，1920×1080 窗口）：**18/18**，6 张截图。量的、不是算的：1920 窗口上工作台这一栏是 **384px**（窗口的 20%）；把旧的默认值存进去再量是 **768px**——同一把尺子上的两倍；**把同一个 dock 切到「文件」tab，栏宽回到 768px**，切回工作台又是 384px；六个按钮是 **23px 的盒子 + 12px 图标**（`icon` 是 29/15）；同一窗口里应用别的图标按钮（右上角 dock 开关）**没跟着变**（33px）；地址栏那一行与选择行在 384px 与 320px 地板上都还是**一行**；预览保住 **812px** 高度；小按钮照样能选中元素（计数 1）并清除（计数 0）。
- `test/panel-width.test.ts`：40% 那几条留着，另加工作台的 20%（`1920 → 384`、`1280 → 320` 落到地板）与两个"不该动"的工作面。typecheck / format:check / oxlint（0 错 0 警）/ web 单测 **2087/2087** 全绿。
- `e2e/dock.spec.mjs`（管面板宽度行为的那一份）：**11 通过 / 1 红**，红的是上游既有的陈旧断言 `getByText("根目录")`（`:275`，在基线上也是红的）。宽度那几条——默认小于 720、拖过旧上限、侧栏让位——全过。

## 边界

- **那一个"存下来的宽度"不区分面板**：拖过分隔线的人，之后每个 tab（包括工作台）都用那个宽度。要让拖拽本身也按面板记，就等于重开"换 tab 整栏跳一下"那条决策，所以没做。
- **量到的数字是桌面壳在**某一个**窗口尺寸下的**。换窗口时默认值按比例走，但在 1600px 以下的窗口里，工作台那一栏会被 320px 的地板接管。
- **`usePanelWidth()`——老的按面板拖拽钩子，连同「窗口变小时把宽度收回上限」的那段钳制——自 dock 接管拖拽之后就没有调用者了。** 于是那段钳制不再运行：在大窗口上拖宽的这一栏，缩到小窗口里也不会被收回，可能把聊天列压到地板以下。这是在量这次改动时发现的，**这次没有修**——它是 dock 重构留下的另一个缺陷，应该有自己的一条决策。
