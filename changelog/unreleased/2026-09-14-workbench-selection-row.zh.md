# 工作台那条选择行收紧到只剩内容

- **Date:** 2026-09-14
- **Type:** fix
- **Scope:** `web`

[English](2026-09-14-workbench-selection-row.md)

放着「多选」黑块与那一排已选 chip 的那条行，**23px 的控件坐在 41px 的行里**：上下各 6.75px 内边距，点亮的多选黑块离这一行自己的上/下边框有 9–10px。现在这层内边距是 **2.25px**，行高 **32px**，黑块到那两条边框的距离是 **4px / 5px**。它上面的地址行**故意没动**。

## 细节

- **只改了一个类**：`features/workbench/workbench-panel.tsx` 里 `px-3 py-1.5` → `px-3 py-0.5`。左右内边距（`px-3`）没变——说的是这一行的上下，不是左边。
- **这条行为什么那么高。** 这一行让子元素居中（`items-center`），而它最高的孩子是一个 chip：文字行高把内容盒撑到 27.5px，于是行高 = `27.5 + 2 × 6.75`。内边距是唯一的杠杆，里面的控件本来就已经在紧凑那一档。
- **为什么量出来是 4 / 5 而不是 2.25。** 23px 的黑块在那个 27.5px 的内容盒里居中，所以到边框的距离是 `2.25 + (27.5 − 23) / 2 ≈ 4.5`——上面进位成 4、下面截成 5。

## 实测

- 新真机脚本 `实测脚本/m62-选择行收紧/`（端口 5194，真桌面壳，1920×1080，预览就是他当时在看的那份演示页）：**8/8**，2 张截图。量到：选择行 **41px → 32px**、上下内边距 **6.75px → 2.25px**、点亮的黑块到这一行边框 **9px/10px → 4px/5px**，而黑块自己**还是 23×23px**；地址行**没变**（48px、上下各 9px）；三个 chip 仍在**同一行**；这一行仍紧贴上面的地址行、下面紧贴预览——收掉的留白没有变成行与行之间的空档。
- `实测脚本/m61-面板宽度与按钮/` 整份重跑：**18/18**，证据刷新——同一块面板的宽度与按钮尺寸行为在行变矮之后原样成立。
- typecheck / format:check / oxlint（1245 个文件 0 错 0 警）/ web 单测 **2087/2087** 全绿；`pnpm --filter @prismshadow/penguin-web build` 干净。

## 边界

- **地址行没碰**（48px、上下各 9px）：这次点名的是选择行，而把那条放着地址输入框的行也收紧，是用户还没做的另一个判断。
- 只在 **zh 界面**、**Linux + Electron**、一个窗口尺寸（1920×1080、工作台按 384px 默认宽度）下量过。320px 地板下两行仍各占一行（m61 覆盖），但那次没有重量留白。
- 这是这条行的第二遍改动：上一次改的是它**里面**的控件，这一次改的是包着它们的**行**。
