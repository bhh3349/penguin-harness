# 工作台的多选：一次挑好几个元素，一条消息带出去（载荷升 v2）

- **Date:** 2026-09-13
- **Type:** feature
- **Scope:** `web`

[English](2026-09-13-ui-workbench-multi-select.md)

工作台的**选择模式**里多了一个态：连点几个元素把它们攒成一批，然后**一条消息**把它们一起交给
Agent。「同一个组件里改三处」「一条链路跨了两个文件」这两种活，现在是一次挑完、一次说完，而不是
挑一个发一条。默认仍然是原来的单选——不碰这个开关的人，看到的还是 L1 那一套。

## 细节

- **多选是选择模式里的一个态，不是第二个模式**（`features/workbench/workbench-state.ts`）。面板上多了
  一枚「多选元素」/「退出多选」的开关；`PickState` 从"一个选中"变成"一串选中"（`picked: ElementFacts[]`）
  加一个 `multi: boolean`，`NO_PICK` 与 reducer 一起跟着走。**开这个态什么都不会变**，只是下一次点击
  的含义从"替换"变成"加进去"。
- **一个元素就是原来那个面板，一点没变**。`currentPick(state)` 取这一串里的最后一个，L1 用"当前选中"做的
  每件事——源码位置解析、载荷卡、§9.4 的边界提示、「已选中 …」那一行——都仍然读这一个元素。所以单选时
  面板与 L1 逐字相同，一批则读作"一批"（计数 + 逐条列表），要细看哪一个就看最后点的那一个。
- **点击的两种含义由面板决定，不由页面决定**（`element-picker.ts`）。拾取器只负责上报"这里被点了"，
  `reducePick` 才决定它是替换还是 toggle（`togglePick`：已经在里面就拿出来——这是"在页面里再点一次就能
  取消"的那条规则，不是新加的第二条）。页面因此不可能画出面板已经丢掉的高亮。
- **高亮从"一个框"变成"一池框"**。拾取器按面板给的列表画**每个 pick 一个绿框**，并在滚动、re-render、
  HMR 之后重画位置；蓝框（悬停候选）只在**没有选中**或**多选态**下跟着光标走——单选锁定之后它不该再动。
  面板与页面之间只有一条真源：面板把选中的选择器列表推给页面（`setPicked`），页面把绿框画成它的样子。
- **单个可取消，两条入口一条规则**：面板里每条 pick 后面有一个 ×，页面里再点一次同一个元素也取消它，
  两条都落到同一个 `unpick` 上。
- **「退出多选」回到单选，并且留下最后点的那一个**（`picked.slice(-1)`）。丢掉整批是丢工作，留下第一个
  是留下用户没在看的那一个——单选 UI 只有一个位置，落点就该是用户刚点过的那个。
- **Esc 还是两段式，只是"一步清一批"**：有选中就先把这一批清空，没有选中才退出选择模式。清空一批不等于
  退出这个模式，一个人按 Esc 想取消的是"我选错了"，不是"我不选了"。
- **一批的身份是元素的集合，不是元素**（`batchRefId`）：chip 的 id 是 `elb-` + 排序后成员 `refId` 的
  FNV，所以同一批换个顺序重挑还是同一条消息（就地更新 chip，而不是多出一个），而它**永远不会**与某个
  元素的 `el-…` 撞上——一批不是元素。

## 载荷：v2 还在，v1 也在

- **形状看个数，不看模式**（`element-payload.ts`）。**一个**元素走的就是原来那个 v1 载荷，一字未改——
  只看过一个元素的 Agent 永远遇不到新形状；**多个**元素走 `schemaVersion: 2`：一个 `page`（一批只能来自
  屏幕上那一个文档）+ `elements: [...]`，每个成员带着 L1 载荷里元素自己的那半（`target` / `source` /
  `style`）。这正是 PRD §6 规则 4 预留的形状。
- **同文件聚合是算出来的，不是排出来的**：`groupByFile` 把成员按源码文件分组，`orderByFile` 是它摊平后的
  顺序——**同一个函数**决定 JSON 里 `elements` 的顺序与消息散文里那几行分组，所以 JSON 与句子不可能对
  哪几处改动属于一起这件事各说一套。定位不到的元素自成一组（`batchNoFile`），不编一个文件给它。
- **消息还是一句话 + 一个 fenced JSON**，只是开头那行人话按文件列：`选中的 UI 元素（3 个，来自 2 个文件，
  同文件的排在一起）：` 下面每行一个文件、文件名后面是它那几个元素（各自带着解析出来的行号）。
- `page` 与 `projectRoot` 都只说一次，chip 上写「3 个元素 / 2 个文件」——用户一眼看到的是这次改动**铺开
  多大**，而不是三个 id。

## 消失的那一个（发送前逐个重读）

- **一批不是"一个更大元素"，所以不套用单元素的那条规则**：发送前逐个重读，**部分元素消失不阻断整批**
  （`batchDecision`）。消失的那几条从这条消息里剔除，其余照发——一个卡片没了就把另外两个改动扣下，
  是让用户为一处失效重做两处有效的活。**全都消失了才扣住**（那时消息里只剩用户的话，没有元素可改）。
- **两个方向的话不一样，因为发生的事不一样**：扣住沿用 L1 的三处话术（面板 / chip 标「已消失」/ toast
  「没有发送」）；部分剔除则在 chip 上标「**少 N 个**」并标红（`ComposerReference.dropped`，与 `stale` 分开：
  这条消息**发出去了**），面板那一行说"消失的那几条已经剔除、其余照发，要带回来回预览里再点一次"。
  两条都是红的，但一条说"没发"，一条说"发少了"。
- **剔除会让消息真的变小**：面板里的 JSON、chip 上的计数、消息里的散文与 `elements` 都按留下来的重建，
  所以用户在面板上读到的 JSON 与走的那一份是同一份。
- 回指刷新的"不张冠李戴"那条不变（M5.1）：解析结果从"一个槽"改成**按选择加键的 Map**
  （`ResolvedSources`，键是页面 URL + 选择器），一批里几个元素同时解析，谁也不会读到别人的文件行。

## 实测

- 真机 `实测脚本/m59-多选/`（端口 5193，真桌面壳 + 真 Vite HMR）：**36/36**。3 个元素跨 2 个文件
  （`h2.card-title` / `p.card-note` 在 `src/App.jsx`，`span.badge` 在 `src/Badge.jsx`）→ **一条**消息、
  **一个** json 块、`schemaVersion: 2`；卡片与消息里的三个位置**逐个等于** AST 真值（不问产品要答案）。
- 同一轮里量了默认单选（`multi: false`，v1）、连点 1→2→3 时面板计数/面板列表/页面绿框三处同步、
  × 与"再点一次"都只摘一条、退出多选留下最后一个；**删掉其中一个**再发送：消息照发、payload 降为 2 个
  元素、面板说「其余照发」、chip 标「少 1 个」；**两个都删掉**再发送：流水一条不涨、toast 说「没有发送」、
  chip 标「已消失」、草稿留着。
- 单测 +20（web 包 2076/2076，147 个文件），typecheck / format:check / oxlint 全绿，web 包 build 通过。

## 边界

- 部分消失只在真机上覆盖了元素被整行删掉的 `missing` 一种理由；`replaced` / `page-changed` 在批量下的
  表现由单元素那条路径的用例保证（m41 / m54）。
- 「少 N 个」那个红 chip 只在发送那一刻存在（发送成功会清空 composer 的引用），真机脚本靠 DOM 变更观察器
  抓它；稳定可读的是面板上那一行。
